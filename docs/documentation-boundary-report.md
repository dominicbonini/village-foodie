## 8. 🔴 How to get this right next time

**The rule already exists and is good. The gap is that a delta is written without it in view.** Three
changes, cheapest first.

### 1. Every block carries a target-document line — the one change that fixes this

Make it the **first** line of each block, before the title:

```
## FOR: reference-manual.md → §4 Plan tiers and feature gating
## FOR: onboarding-flow.md  → §15A The setup wizard as it stands
## FOR: reference-manual.md → NEW SECTION (no existing heading fits — justify below)
```

Two properties matter more than the format:

- 🔴 **The document is named explicitly.** A heading alone is ambiguous across three maintained
  documents; a filename is not.
- 🔴 **"NEW SECTION" must be declared deliberately, not arrived at by accident.** Both §51 and §52 were
  created because a heading did not exist — **the editor's fallback silently became a decision.** When
  the delta says NEW SECTION, that is your choice; when it names a section, a missing one is a **STOP**,
  not a licence to invent.

### 2. A routing rule at the top of every delta, copied from where it already lives

Paste this into each delta so it is in front of whoever applies it:

> **ROUTING.** `onboarding-flow.md` owns the **flow an operator experiences** and the decisions behind
> it. `reference-manual.md` owns **schema facts, cross-cutting invariants (§35) and the backlog (§27)**,
> and is **authoritative where the two overlap**. A mechanism's own section owns that mechanism's limits
> (§4 for the parity checker). **Cross-reference rather than restate.** If a block is both a story and a
> rule, **split it**: the rule to §35, the story to its subject document.

**That is your own line from `onboarding-flow.md`:5, plus the split instruction.** The split is the part
that was missing — the front-door incident was one block containing both, and undivided it went to the
wrong document whole.

### 3. Ask for the inventory before writing, and make the editor report placement

- **Before writing a delta:** *"list the maintained documentation files and their section headings"* —
  two minutes, and it is the input you said you did not have.
- **In the delta's instruction header, add:** *"For every block, report the file and section it landed
  in, and flag any block whose target did not exist rather than creating one."* You get the misroutes
  in the report instead of finding them three deltas later.

### What I would not do

⚠️ **Do not merge the two documents.** The split is right — one is a journey, one is a subject
reference, and they are read at different moments.
⚠️ **Do not automate the routing.** Judgement is the work; the fix is putting the rule and the inventory
in front of the judgement.
