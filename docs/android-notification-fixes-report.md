### What each expects — a filename, a resource name, or a path

🔴 **Neither, exactly: on Android the plugin STRIPS the extension and treats the remainder as a raw
resource name.** Read from the installed plugin source, `LocalNotification.java:85-99`:

```java
    public String getSound(Context context, int defaultSound) {
        String soundPath = null;
        int resId = AssetUtil.RESOURCE_ID_ZERO_VALUE;
        String name = AssetUtil.getResourceBaseName(sound);
        if (name != null) {
            resId = AssetUtil.getResourceID(context, name, "raw");
        }
        if (resId == AssetUtil.RESOURCE_ID_ZERO_VALUE) {
            resId = defaultSound;
        }
        if (resId != AssetUtil.RESOURCE_ID_ZERO_VALUE) {
            soundPath = ContentResolver.SCHEME_ANDROID_RESOURCE + "://" + context.getPackageName() + "/" + resId;
        }
        return soundPath;
    }
```

and `AssetUtil.java:341-357` (in `@capacitor/android`):

```java
    public static int getResourceID(Context context, String resourceName, String dir) {
        return context.getResources().getIdentifier(resourceName, dir, context.getPackageName());
    }

    public static String getResourceBaseName(String resPath) {
        if (resPath == null) return null;
        if (resPath.contains("/")) {
            return resPath.substring(resPath.lastIndexOf('/') + 1);
        }
        if (resPath.contains(".")) {
            return resPath.substring(0, resPath.lastIndexOf('.'));
        }
        return resPath;
    }
```

**So `'beep.wav'` → base name `'beep'` → `getIdentifier("beep", "raw", pkg)`.** It wants
`res/raw/beep.<ext>`. A path would also work (last segment taken); a bare `'beep'` would work.

### 🔴 What Android does when it cannot resolve it — a SILENT fallback, not an error

**Stated plainly, as asked: it is a silent fallback. There is no error, no throw, no rejected plugin
call and nothing logged.**

The chain, all the way through:

1. `getIdentifier("beep","raw",pkg)` → **0** (`RESOURCE_ID_ZERO_VALUE`).
2. `resId = defaultSound` — which comes from `getDefaultSound()`, `LocalNotificationManager.java:442-455`:
   it reads the **config** `sound`, applies the *same* base-name + raw lookup, and is therefore **also 0**.
3. `resId == 0` → `soundPath` stays `null` → `getSound()` returns `null`.
4. `LocalNotificationManager.java:195-204`:

```java
        String sound = localNotification.getSound(context, getDefaultSound(context));
        if (sound != null) {
            …
            mBuilder.setSound(soundUri);
            mBuilder.setDefaults(Notification.DEFAULT_VIBRATE | Notification.DEFAULT_LIGHTS);
        } else {
            mBuilder.setDefaults(Notification.DEFAULT_ALL);
        }
```

**The `else` branch — `DEFAULT_ALL` — is the system default sound, vibrate and lights.** Which is
almost certainly what anyone testing this heard, and why a missing file was never noticed.

## 3. iOS — is it affected, and how do sounds resolve there?

### The icon: **iOS is NOT affected at all.**

`grep -rn "smallIcon" node_modules/@capacitor/local-notifications/ios/` → **ZERO HITS.** The iOS plugin
has no `smallIcon` concept; the key is inert there. Defect (b) is Android-only.

### The sound: iOS resolves it differently, and **a single filename CAN serve both**

`LocalNotificationsPlugin.swift:283-285`:

```swift
        if let sound = notification["sound"] as? String {
            content.sound = UNNotificationSound(named: UNNotificationSoundName(sound))
        }
```

**iOS takes the string WHOLE — filename plus extension — and looks it up in the app bundle
(and `Library/Sounds`).** Android takes it MINUS the extension and looks it up in `res/raw`.

🔴 **THE STOP CONDITION DID NOT FIRE.** The two conventions are complementary, not contradictory:
`'beep.wav'` resolves as `res/raw/beep` on Android and as the bundle file `beep.wav` on iOS. **One
string serves both** — which is precisely what Capacitor's extension-stripping is for. So there is
nothing to escalate here.

**iOS is affected by defect (a) identically:** the file is missing from the iOS bundle too
(`find ios -name "*.wav" -o -name "*.caf" -o -name "*.aiff"` → **zero**). An unresolvable
`UNNotificationSoundName` falls back to the default alert sound — ⚠️ **INFERRED**, Apple behaviour, not
read from this repo. **No iOS file was changed by this task.**

⚠️ **A side-finding, reported and NOT acted on** (outside the stated scope): the two `sound: 'default'`
values are also not what they look like. On Android `'default'` → base name `'default'` →
`getIdentifier("default","raw",pkg)` → 0 → same silent fallback. On **iOS** it asks for a bundle file
literally named `default`, which does not exist — it does **not** mean "the system default". Both are
inert-to-harmless today, but they are the same class of defect as `beep.wav`. **Left alone: the brief
named `beep.wav`, and removing more would be scope creep. Flagging rather than choosing.**
