# HatchGrab — European SEO & product glossary (v1, 20 October 2026)

**Purpose.** The locked terms every translation of HatchGrab must use, so the words on our pages match what food
truck operators (B2B) and their customers (B2C) actually search for and say. Translators (human or AI) must use the
**Use** column. Alternatives may appear in body copy for SEO breadth but never replace the Use term in headings,
buttons or feature names.

**Evidence and limits.** Built from how vendor sites, trade bodies, regulators, festivals and press in each country
word these concepts (October 2026). **No search-volume tool was used**, so "Conf." = consistency of real-world use,
not traffic. Low-confidence terms must be checked by a native speaker (and, ideally, Google Keyword Planner) before
the language goes live.

## Global rules (all languages)

1. **HatchGrab** is the brand: never translated. **Pro** stays as a plan name everywhere.
2. **"Pay at Hatch" is translated** (decided 20 Oct 2026) — the idea is *the customer orders online in advance and
   pays in person when collecting at the truck*. Never translate the word "hatch"; it means nothing in these
   languages. Never imply cash only (card at the truck is fine).
3. **Food truck** and **street food** stay close to English in every language, but **spelling differs** (DE
   "Foodtruck", NL "foodtruck", FR/ES/IT "food truck"). Use the local spelling exactly.
4. **"Menu" is a trap in DE, FR, ES and NL**: the local "menu" word often means a *set meal / combo*. The list of
   dishes is a different word (see each table). Feature names must use the right one.
5. **"Commission"**: say "0% … on orders" and state card fees separately — in several languages the commission word
   also covers card fees.
6. **Plan names, plan descriptions and subtitles are data** (`plans` table) and are currently English only — they
   need per-language versions (see the build note at the end).
7. Regional variants (AT, CH, BE) are **overrides** on the language base file, the same pattern as en-GB/en-US.
8. Use the country's own payment words on customer pages: iDEAL (NL), Bancontact (BE), TWINT (CH).

## Build notes for the language work (for the agent)

- One base messages file per language (`de`, `nl`, `fr`, `es`, `it`) plus country overrides (`de-AT`, `de-CH`,
  `nl-BE`, `fr-BE`, `fr-CH`), the same pattern as `en-GB` + `en-US`. Ireland = `en-IE` override on `en-GB`
  (euro, minimal wording).
- **Plan names, descriptions and subtitles** live in `plans` (English only). They need per-locale versions (e.g. a
  `plan_translations` table, or message keys looked up by plan key with the DB value as the en-GB fallback) — design
  this before the first non-English language.
- Every term in the **Use** columns becomes a glossary the translation step must follow; low-confidence rows are
  flagged for native review before go-live.
