## 1 · The renderer: what was chosen, why, and how fast it is

**Chosen: satori + resvg, through `next/og`.**

It was evaluated against the brief's four constraints before anything was built, and the decision was
made by running it rather than by reading about it:

| Constraint | satori + resvg (`next/og`) | sharp compositing SVG text |
|---|---|---|
| Runs on Vercel serverless without native-binary problems | **Yes — both are WASM** (`next/dist/compiled/@vercel/og/resvg.wasm`, `yoga.wasm`) | **No** — a native binary per platform. This repo already works around exactly that trap: `next.config.ts` carries a `serverExternalPackages` entry for `@sparticuz/chromium` because its binary must not be bundled |
| Custom bundled fonts | Yes, first-class (`fonts: [{ name, data, weight }]`) | Yes, but text layout becomes ours |
| Absolute positioning + background image | Yes | Yes |
| Under 2s for 1080×1920 | **~40ms warm** | untested — it was not needed |
| New dependency? | **None.** It ships inside Next 16 | Yes |
| Text layout | Flexbox via yoga — line breaking, alignment, shrink | **None.** We would own wrapping and positioning on top of the metrics we already have to own |

**Measured render times** (same machine, in the harness):

| Image | Cold (first call, fonts parsed) | Warm |
|---|---|---|
| 1080×1350 poster, 7 days, 2 stacked | **~330 ms** | **~40 ms** |
| 1080×2400 → capped to 972×2160 | **597 ms** | — |

The brief's ceiling is 2 s. The cold number includes parsing up to five TTFs; they are cached per
process, so a warm serverless container pays the 40 ms.

**One renderer, and nothing imitates it.** The setup preview, the weekly-post preview and the
downloaded file are all `renderWeeklyPost()`'s PNG. There is no HTML lookalike anywhere in
`components/manage/WeeklyPost.tsx` — the brief's reason is exact, and it is the whole design: what the
operator approves must be what they download, and a CSS imitation drifts from the renderer the first
time either is touched, silently, on artwork that goes out to a truck's customers.

What the browser *does* draw is the dashed outlines on top of that PNG. Dragging moves them instantly;
a 400 ms debounce re-renders the picture underneath. So the gesture is immediate and the truth arrives
a moment later, rather than every drag waiting on a round trip.

## 2 · The fonts

21 families, 36 files, **6.3 MB**, committed under `assets/fonts/weekly-post/` with
`MANIFEST.json` recording what was fetched and from where.

**Read from disk, never fetched at render time.** A render-time fetch would make the output depend on
the network and on whichever version Google is serving that week — every `v57` in those URLs has been
`v53` and will be `v61`, with different metrics. `scripts/_fetch-weekly-post-fonts.cjs` is the recorded
provenance and the way to add or refresh a family, deliberately, as a committed diff.

**Licences are the real ones**, read from the directory `google/fonts` keeps each family in (`ofl/`
vs `apache/`) — the authoritative answer. `fonts.google.com/metadata/fonts` carries only an
`isOpenSource` boolean, which cannot tell OFL-1.1 from Apache-2.0. Two of these are **Apache-2.0, not
OFL**, and are labelled as such rather than rounded up:

| Group | Families | Licence |
|---|---|---|
| **Bold condensed** | Oswald (400/700), Bebas Neue (400), Anton (400), Archivo Black (400), Teko (400/700) | OFL-1.1 |
| **Slab & serif** | Playfair Display (400/700), Merriweather (400/700), Bitter (400/700), Abril Fatface (400) | OFL-1.1 |
| | **Roboto Slab (400/700)** | **Apache-2.0** |
| **Handwritten** | Kalam (400/700), Caveat (400/700), Pacifico (400), Dancing Script (400/700) | OFL-1.1 |
| | **Permanent Marker (400)** | **Apache-2.0** |
| **Clean sans** | Inter (400/700), Montserrat (400/700), Poppins (400/700), Raleway (400/700), Work Sans (400/700), Lato (400/700) | OFL-1.1 |

**Single-weight families list only 400, and that is load-bearing.** Asking Google for a 700 of Anton
returns the 400 file; storing it as "bold" would make a bold toggle silently do nothing. `resolveWeight`
falls back visibly, and satori is never asked to synthesise a bold (which smears the outline and looks
like a rendering fault).

**Vercel is told about them explicitly.** `next.config.ts` gained an `outputFileTracingIncludes` entry
for `/api/weekly-post`: a file read with `fs` at a runtime-built path is invisible to the tracer, so
without it the fonts would be present locally and **absent in production** — the hardest shape of bug
to diagnose from a deploy. Keyed on the one route that renders, so 6.3 MB is not added to every
function.

## 3 · The layout JSON

Stored in `truck_post_designs.layout`, validated by `validateLayout()` in
[lib/weekly-post/layout.ts](../lib/weekly-post/layout.ts) **before every write and before every
render**. Coordinates are always in the **blank image's own pixels** — the editor's scale factor never
reaches storage, so a design made on a phone renders identically to one made on a desktop.

```jsonc
{
  "version": 1,
  "width": 1080, "height": 1350,        // the blank's native size, from the stored file

  "heading": {
    "x": 64, "y": 94, "w": 952, "h": 108,
    "text": "Week commencing {start} to {end}",   // {start} and {end} are the only tokens
    "fontId": "anton", "fontSize": 54, "bold": false,
    "color": "#ffffff", "align": "center",
    "caps": true, "raisedOrdinals": false,
    "bgSample": { "r": 31, "g": 28, "b": 40 }     // written by the editor; null = not sampled
  },

  "date": {
    "x": 64, "y": 270, "w": 285, "h": 113,
    "fontId": "oswald", "fontSize": 38, "bold": true,
    "color": "#ffffff", "align": "left",
    "caps": true, "raisedOrdinals": true,
    "twoLines": true,                              // "MONDAY" / "28TH SEPTEMBER", or one line
    "bgTrading": null,                             // optional panel on a trading day
    "bgDayOff": "#00000055",                       // optional panel on a day off
    "bgSample": { "r": 40, "g": 30, "b": 35 }
  },

  "location": { /* same fields, no twoLines/bg* */ },
  "time":     { /* same fields */ },
  "note":     null,                                // or the same fields again

  "rowSpacing": 145,            // row 1's boxes + spacing × n = rows 2–7
  "daysOffText": "No trading today",
  "timeStyle": "12h",           // "12h" → 5pm – 8pm · "24h" → 17:00 – 20:00
  "keepReadable": true,
  "showCancelled": true,
  "exampleOpacity": 0
}
```

**Rows 2–7 are row 1's boxes, offset.** Storing seven sets would let them drift apart and would make
"the other six days copy it" a promise the data could break.

**What the validator refuses**, with a plain sentence an operator can act on: a non-object; a wrong
`version`; `NaN` or `Infinity` anywhere (both are `typeof number` and reach satori as `left: NaN`,
which draws nothing and reports nothing); a numeric **string**; a box that reaches outside the image; a
negative position; a missing box; `rowSpacing` of 0 or taller than the image; a heading over 200
characters.

**What it normalises instead of refusing**, because a drag can legitimately produce it: an unknown font
→ the default; a malformed colour → white; an out-of-range background sample → **null**, not a clamped
guess, because a clamped bad sample is a confident wrong answer about readability.

**The image size comes from the server, never from the payload.** A client that could declare "this
blank is 9000×9000" could place a box anywhere and have the bounds check wave it through. Asserted.

**A design whose seventh row falls below the image saves and warns** — the operator may genuinely want
the last row near the edge, and refusing to save would be worse than telling them.

## 4 · How each piece behaves

| | |
|---|---|
| **Week** | Monday–Sunday, Europe/London. Everything is calendar-date arithmetic at UTC noon, so a DST change **cannot** shift a day. Picker defaults to **next week from Friday 00:00** — a date test, not a clock test, because 00:00 is the start of the day. |
| **Heading** | Editable, `{start}`/`{end}`, "Monday 28th September". Capitals and raised ordinals. An unknown token is left visible rather than silently blanked. |
| **Date** | Two lines by default, or one. Ordinals correct for 1st/2nd/3rd/11th/12th/13th/21st/31st — the teens are checked **first**, which is the whole bug. |
| **Raised ordinals** | Separate runs, **never a Unicode superscript character** — not every bundled family carries ᵗʰ, and a missing glyph is a blank box on a poster. |
| **Location** | The place's "Name on posts" via the existing `placeForEvent`, falling back to `venue_name`; `short_name` wins when set, because that is the field filled in *because* the full name does not fit. Town on a smaller second line when known **and not already in the name** — "Lavenham Village Hall / Lavenham" is noise on seven rows. |
| **Time** | `5pm – 8pm` (minutes only when not :00) or `17:00 – 20:00`. En dash with spaces. A missing end time gives just the start, never a dangling dash. |
| **Day off** | Location shows the days-off text; **no time box at all**; the Date box takes the days-off background. |
| **Cancelled** | Location struck through **per entry**, Time reads `CANCELLED`. A day with one cancelled event and one going ahead strikes only the cancelled one. "Show cancelled events" defaults on. |
| **Stacking** | 1–4+ events in a day, sorted by start time, tie-broken by name then id so a poster never changes when nothing changed. Text shrinks; if it still cannot fit, lines are dropped rather than overflowing, and that is reported. |
| **Statuses** | confirmed, unconfirmed and **closed** all trade — a poster for the current week must still show Monday. An unknown status trades rather than vanishing. |
| **Powered by HatchGrab** | Always, bottom centre, small, under the same readability rule. It is our mark on someone else's artwork and must not be the one illegible thing on it. |

### Shrink to fit — four defences, in order

1. **Shrink.** Step the size down until the longest line fits the width and all lines fit the height.
2. **A floor** at 35% of the chosen size (minimum 8px). Below that the poster looks broken rather than
   tidy.
3. **Truncate** with an ellipsis, **by code point** — slicing a surrogate pair in half is literally the
   "clip mid-glyph" the brief forbids — with the ellipsis's own width reserved first.
4. **Tell the operator**, naming the day. A silently shortened place name is the one failure they
   cannot see coming.

Measured with the fonts' **own metrics**: `lib/weekly-post/ttf-metrics.ts` reads `head`, `cmap` and
`hmtx`. Nothing in the dependency tree can measure text — satori measures internally and exposes
nothing, and there is no canvas or opentype.js — and the alternative was a render → decode → shrink →
render loop of 40 ms renders per box per day that would still be guessing which size to try next.

### Readability — where the sampling happens, and why

The rule: sample the blank under each box; if WCAG contrast against the chosen colour is below 4.5:1,
add a soft shadow in the **opposite tone of the text**. **The operator's colour is never changed** —
silently darkening their white text would be editing their design.

**The sampling runs in the browser and the deciding runs on the server**, and that split is deliberate.
Sampling needs the blank's *pixels*, which means decoding a PNG **or a JPG**; there is no sharp, no
canvas and no jpeg library on the server, and satori takes an image in without ever exposing pixels.
The browser has a decoder for both. So the editor samples each box with a canvas when it is placed or
moved and stores the average in the design; `lib/weekly-post/contrast.ts` decides, purely and
server-side, and the renderer draws.

**No sample ⇒ no shadow.** A design with none (an older editor, or a canvas the browser refused as
tainted) renders exactly as the operator's colours say. Guessing a background and adding a shadow
nobody asked for would alter artwork on no evidence.

Luminance uses the **sRGB transfer function, not a plain average**: `(r+g+b)/3` gets blue and yellow
the wrong way round, so a plain average decides white-on-blue is unreadable (it is 8.6:1 and perfectly
fine) and adds a shadow to text that did not need one.

## 5 · The migration

**File:** `supabase/migrations/20261006_truck_post_designs.sql`. Idempotent.

### 5.1 The bucket — this repo has never created one in SQL

`truck-media` and `outreach-attachments` were both made by hand in the Supabase dashboard; **no
migration in this tree creates a bucket.** The brief says to create it in the migration "if that is how
this repo does buckets; otherwise say how" — it is not how this repo does it, so, said out loud:

- the `insert into storage.buckets` below is the standard Supabase way and is idempotent;
- **if your SQL-editor role cannot write `storage.buckets`**, that one statement errors and the rest of
  the migration still applies — create it by hand instead: Storage › New bucket, name `post-designs`,
  **Public: OFF**;
- **it must be private.** The browser never gets a public URL; the server mints 1-hour signed URLs with
  the service-role key. A public bucket would make every truck's artwork world-readable by guessing a
  path.

### 5.2 The SQL

```sql
set lock_timeout = '3s';

begin;

insert into storage.buckets (id, name, public)
values ('post-designs', 'post-designs', false)
on conflict (id) do nothing;

create table if not exists public.truck_post_designs (
  id uuid primary key default gen_random_uuid(),
  truck_id text not null references public.trucks(id) on delete cascade,
  kind text not null check (kind in ('week')),
  blank_path text not null,
  example_path text,
  width int,
  height int,
  layout jsonb not null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  constraint truck_post_designs_blank_not_blank check (length(btrim(blank_path)) > 0)
);

create unique index if not exists truck_post_designs_truck_kind_uidx
  on public.truck_post_designs (truck_id, kind);

alter table public.truck_post_designs enable row level security;
drop policy if exists "service_role only" on public.truck_post_designs;
create policy "service_role only" on public.truck_post_designs
  for all to service_role using (true) with check (true);
revoke all on public.truck_post_designs from anon, authenticated, public;

comment on table public.truck_post_designs is
  'The truck''s own blank weekly-schedule artwork and the positions of the text boxes HatchGrab fills in. One row per truck per kind; kind is ''week'' only in stage 1. Images live in the PRIVATE post-designs bucket and are served to the browser as short-lived signed URLs. The layout jsonb is validated by validateLayout() in lib/weekly-post/layout.ts before every write.';

comment on column public.truck_post_designs.layout is
  'Box positions in the BLANK IMAGE''S OWN PIXELS (never editor-scaled coordinates), plus fonts, colours, row spacing and the per-box background sample used by the readability rule. Shape and bounds: lib/weekly-post/layout.ts. version must match LAYOUT_VERSION.';

commit;

notify pgrst, 'reload schema';
```

`truck_id` is **text**, not uuid — `trucks.id` is a slug like `pizzeria-gusto`, and uuid fails the
migration outright. `kind` is CHECKed to `'week'` rather than left free text, and the unique key is
`(truck_id, kind)` so the single-event post can add a value and a second row later.

## 7 · Harness results

### 7.1 `scripts/weekly-post.cjs` — new. **121 checks, 15 broken variants, all pass**

No network, no database, no browser, no real truck artwork. Sections: the week · ordinals, dates and
times · the week's data · shrink to fit · readability · the captions · layout validation · uploads ·
**the render, checked in the pixels** · the variants.

**The pixel checks are real pixel checks.** `scripts/_png-decode.cjs` is a minimal PNG reader (zlib +
the five filter types) written for this, so the harness can look at what came out rather than trusting
the measurement that decided the font size — which is the only way to catch the measurement and the
renderer *disagreeing*, and that disagreement is invisible until it is on artwork a truck has posted.

- **Every day's Date, Location and Time stays inside its box.** The poster is rendered with one box
  type at a time (the others parked in an 8×8 corner) and diffed against the same poster with that box
  parked too — so every differing pixel belongs to that box and nothing else. Each day's row band is
  then checked across the full width.
- **"Powered by HatchGrab" is drawn**, bottom centre, within 8% of the middle.
- **The readability shadow** is applied on a low-contrast box (pixels differ) and **not** on a
  high-contrast one (byte-identical).
- **Shrink-to-fit across all 21 families and both weights**, four strings, three box sizes — 504 cases,
  none exceeding its box.

| Variant | The bug it reinstates |
|---|---|
| V1 | "11st September" — the teens stop being special-cased |
| V2 | the weekday numbering reverts to Sunday-first — every week starts on the wrong day |
| V3 | the picker stops defaulting to next week on a Friday |
| V4 | a cancelled event is shown as trading — customers sent to an event that is not happening |
| V5 | a **closed** event stops counting as trading — today vanishes from this week's poster |
| V6 | the minimum size floor is removed — a long name renders at 1px instead of truncating |
| V7 | the ellipsis is appended without reserving room — "shortened to fit" still overflows |
| V8 | luminance becomes a plain average — white on **blue** gains a shadow it does not need |
| V9 | the validator accepts `NaN` — the box silently draws nothing and reports nothing |
| V10 | the validator trusts the payload's own width — an off-image box passes |
| V11 | the minimum upload size is dropped — an 80px blank is accepted and renders as mush |
| V12 | a lunchtime event is posted as "tonight" |
| V13 | a cancelled event still carries an ordering link |
| V14 | an oversized blank stops scaling as one — the text lands in the wrong place |
| V15 | a note the operator wrote never reaches the poster |

**Four variants had to be rewritten because they could not fail**, and each one taught something worth
recording:

- **V2** was going to be the classic "+24 hours per day" DST bug. It could not be made to fail — and
  the reason is a fact about the feature, not about the test: **the clocks always change at 02:00 on a
  Sunday, which is the last day of a Monday-start week, so that day's local midnight is still on the
  old offset and every day is exactly 24 hours after the one before.** The DST assertions in §1 are
  guarding against something this calendar cannot produce. V2 now targets the mistake that *can*
  happen: `Date.getDay()` is Sunday-first and this module is Monday-first.
- **V8** first used white-on-yellow, which is unreadable under *both* formulas. Blue is where they
  genuinely disagree.
- **V9** removed `Number.isFinite` only — and `NaN >= min` is false, so the range test rejected it
  anyway. That is a small piece of good news about the validator (two independent guards); the variant
  now removes both.
- **V15** tested that an *empty* note box is not drawn, which has no pixels either way. It now tests the
  direction that does: a note the operator wrote must appear.

### 7.2 Three bugs the harness found in the code

1. **The fit floor was applied to width only.** "Great Waldingfield Recreation Ground" in a 160×28 box
   shrank to the floor and truncated — fixing the width — but one line of Oswald at 20px is 29.6px
   tall, so it still overflowed **vertically**, and truncation cannot fix height. The search ceiling is
   now clamped by what the height allows *before* it begins, and when that is below the proportional
   floor, **height wins**: small-but-whole beats large-and-clipped. Found by the all-families sweep.
2. **`Date.UTC` rolls over silently.** `Date.UTC(2026, 12, 99)` is not an Invalid Date — it is 7 April
   2027. `2026-02-30` and `2026-13-99` were both accepted and came back as real dates in the wrong
   month, which for this module means a poster for the wrong seven days with no error anywhere. The
   date is now round-tripped through its components.
3. **The superscript sat on the baseline.** satori aligns a flex row on the baseline, so the smaller
   "TH" rendered at the foot of the "28" rather than raised; `marginBottom` did nothing. Visible in the
   first example render. The row is now top-aligned, which *is* the superscript position for a smaller
   run and is identical for runs of equal size.

### 7.3 A fourth, found by the production build

The font list was reaching a `'use client'` component through `layout.ts`, dragging **`node:fs` into
the browser bundle**. `npm run build` failed with "Code generation for chunk item errored" on
`app/manage/[token]/page.tsx`. Split into **`font-list.ts`** (pure data — families, ids, weights,
licences, `resolveWeight`) and **`fonts.ts`** (the bytes, server-only, re-exporting the list). `tsc`
and the harness were both clean before this; only the real build caught it.

## 8 · Test list for localhost — Village Spice

Start at `http://localhost:3000/login`. **Village Spice only.** Do not open Pizzeria Gusto.

**Run the migration first** (§5). Without it the screen says so plainly rather than looping on "set up
your weekly post".

1. **Open it.** Manage → Schedule → **Weekly post**. With no design you should land straight on the
   setup screen with the Canva note (remove your text boxes, then Share › Download › PNG).
2. **Upload a blank.** Any PNG or JPG at least 600px on the short side. A too-small or non-image file
   must be refused with a sentence, not a code.
3. **The boxes appear** at a starting position with seven rows inside the frame. The centre shows the
   real rendered poster with next week's (or this week's) events already in it.
4. **Drag the Date box** with the mouse. The outline moves instantly; the picture updates about half a
   second after you let go.
5. **Resize it** by a corner handle. Then do both again **on an iPad with your finger** — this is the
   one that matters, and the page must not scroll while you drag.
6. **Place Location and Time.** The six faint rows below show where the other days will land; adjust
   **Rows › Spacing** until they sit where your artwork expects.
7. **Press "Preview a busy week".** You should see a 54-character place name, two events stacked on a
   Saturday, a cancelled day and days off — the worst case, before it happens. Check nothing overflows.
8. **Change the Date box's font, size and colour**, turn on **Capitals** and **Raised ordinals**, and
   set a **background on days off**. Each change re-renders.
9. **Save design.** If the last row falls below the image you are told, and it still saves.
10. **Generate This week and Next week.** Switch between them on the post screen; the picture and the
    caption both change.
11. **Untick an event** and confirm it leaves both the image and the caption. Toggle **Show cancelled
    events**.
12. **Write a note.** It appears in the caption, and in the note box if you placed one.
13. **Download image.** The file should be the same picture you are looking at, at the blank's native
    size (capped at 2160px on the longest side).
14. **Share, on a phone.** The caption is copied to the clipboard *first*, then the native share sheet
    opens with the PNG. Where file sharing is unsupported it falls back to a download plus "caption

15. **Copy caption**, and paste it somewhere to check it reads properly.
16. **Copy a per-event post.** Check the wording against today: an event today starting at 17:00 or

17. **Replace the blank with a different size** and confirm you are told the boxes have been reset;
    replace it with the *same* size and confirm your design survives.
18. **Check the gate.** On a Starter truck the whole pane should show the upgrade message — and the

## 9 · Noticed, not changed

1. **`scripts/add-order-refresh-inputs.cjs` is intermittently flaky.** It failed twice during this
   build (once in a sweep, once in isolation) naming a *different* variant each time, then passed
   **eight consecutive runs** in isolation. Nothing in this build touches the dashboard or add-order
   code. It looks timing-sensitive under CPU load; the 84/84 above is from a sweep run with nothing
   else competing. Worth making deterministic before it erodes trust in the sweep.
2. **`truck_post_designs` is not in the schema census.** It qualifies (created by a migration) and
   adding it is one line in `scripts/_outreach-schema-census.cjs`. Left out deliberately this build —
   the table is brand new and the feature's columns may still move.
3. **The weekly post's per-event "Share" button currently copies the text**, the same as "Copy text".
   Sharing a single event's text *and* a per-event image is a stage-2 shape (there is no per-event
   image yet), and a share sheet with only text is worse than a copy. Flagged rather than silently left
   looking like a duplicate button.
4. **`Toggle` is defined inside `app/manage/[token]/page.tsx` and not exported**, so the weekly post
   has a local copy of it. Copying ~6 lines was the smaller wrong than exporting a component out of a
   14,000-line page file as a side effect of this build. Worth unifying deliberately.
5. **The editor samples the blank through a canvas**, which requires the Supabase signed URL to send
   permissive CORS headers. If it does not, the sample silently becomes "no sample" and the readability
   shadow is simply never applied — correct and safe, but it would be invisible. Worth confirming on
   the real bucket during test 8.
6. **`<img>` rather than `next/image`** in the weekly-post screens (3 ESLint warnings). The preview is a
   blob URL from a POST response and the blank is a signed URL — neither is optimisable, and
   `next/image` would break the object-URL lifecycle.
7. **The 2160px cap is applied at render, not at upload.** A 4000px blank is stored at full size and
   scaled on every render. Capping on upload would need an image *encoder* on the server, which is the
   same gap as the readability sampling; storing the original is what the brief asks for.
8. **Out of scope, as instructed, and untouched:** single-event post, place pictures, AI, ready-made
   designs, posting to Facebook, per-van images. Nothing in ordering, KDS, payments or the public
   schedule page was changed.
