## 1. THE FIX — expandable text

### What was built

A small component, `SavedAllergenCard`, defined at `app/manage/[token]/page.tsx:1092-1170`, immediately
above `AllergenWizardModal` so both call sites can reach it.

```tsx
function SavedAllergenCard({ text, url, clampClass, className = '' }: {
  text: string
  url: string
  clampClass: string
  className?: string
}) {
  const [expanded, setExpanded] = useState(false)
  const [clipped, setClipped] = useState(false)
  const textRef = useRef<HTMLParagraphElement | null>(null)

  useEffect(() => {
    const el = textRef.current
    if (!el || expanded) return
    const measure = () => setClipped(el.scrollHeight > el.clientHeight + 1)
    measure()
    const ro = new ResizeObserver(measure)
    ro.observe(el)
    return () => ro.disconnect()
  }, [text, expanded, clampClass])
  …
```

**(a) Show more / Show less.** `expanded` is `useState` inside the component. It is never persisted,
never sent anywhere, and dies with the component — the comment says why: *"which panel someone left open
is not a fact about the truck, and persisting it would mean a write on a read."*

**(b) 🔴 It renders ONLY when the text is genuinely clipped — measured, not guessed.**

```tsx
{(clipped || expanded) && (
  <button type="button" onClick={() => setExpanded(v => !v)} …>
    {expanded ? 'Show less' : 'Show more'}
  </button>
)}
```

`clipped` is `el.scrollHeight > el.clientHeight + 1` on the **collapsed** paragraph. A character-count
heuristic would be wrong in both directions — a short wide line and a long narrow one clamp differently —
so the element is asked directly.

⚠️ **Three details that matter:**

- **Measurement is skipped while expanded** (`if (!el || expanded) return`), because with the clamp off
  the two heights always match. `clipped` keeps its last collapsed reading, which is what lets
  "Show less" stay on screen.
- **A `ResizeObserver` re-measures when the column changes width**, since a card that fits at one width
  clips at another. Disconnected on cleanup.
- **`clampClass` is passed as a literal string**, never interpolated. `line-clamp-${n}` would not be
  generated by Tailwind at build time and would silently produce no clamp at all.

**(c) Read-only.** Section 5.

### The call site

`app/manage/[token]/page.tsx:4288-4298` — the inline block is replaced by:

```tsx
<SavedAllergenCard
  text={allergenInfoText}
  url={allergenUrl}
  clampClass="line-clamp-3"
  className="mt-3"
/>
```

Same clamp (3 lines), same `mt-3`, same green panel styling — carried into the component's own
`border border-green-100 bg-green-50 rounded-xl p-3`.

## 3. THE LATENT BUG — fixed, and the wizard reported rather than guessed at

### The Menu tab is fixed

**Before**, the whole panel was gated on the text, with the link nested inside:

```tsx
{allergenInfoText && (
  <div …>
    <p …>{allergenInfoText}</p>
    {allergenUrl && <a …>View original card</a>}
  </div>
)}
```

so a truck with a file and no text got `hasCard === true` → the green *"allergen card saved"* → **and
then nothing**.

**After**, the gate lives in the component and covers both columns:

```tsx
if (!text && !url) return null
…
{text ? ( …clamped text + Show more… ) : (
  <p className="text-xs text-slate-600">
    A card file is saved for this truck, but no summary text was stored. Open the original to read it.
  </p>
)}
{url && ( …the link… )}
```

**A url-only truck now shows a sentence explaining what it has and a link to open it** — meaningful,
rather than an empty panel. ⚠️ `hasCard` at `:4243` is **unchanged** (`!!(allergenInfoText ||
allergenUrl)`): it was never wrong; the preview was the half that disagreed with it, and now they agree.

Adopting it means adding `heading` and `footer` (or `children`) props and changing what the modal shows.
**You told me not to change the wizard as a guess, and I cannot see the modal**, so I did not.

**What the wizard would need**, precisely:

2. Its outer condition changed from `) : cardText ? (` to `) : (cardText || cardUrl) ? (` — otherwise the
   url-only case still cannot reach the panel there.
3. The call becoming
   `<SavedAllergenCard text={cardText} url={cardUrl} clampClass="line-clamp-6" className="p-4" heading={…} footer={canEdit && …} />`.

⚠️ **Step 2 is the actual bug fix; steps 1 and 3 are the de-duplication.** They can be done
